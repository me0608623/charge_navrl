⭐⭐ **提早 return 跳過副作用記帳** —— 2026-07-27 走廊 motion family 比例卡在
`[32.3%, 38.0%, 29.8%]`（longitudinal +4.6pp），**兩次獨立執行停在同一數字**（故非收斂慢）。

**診斷關鍵**：把補償機制的**內部帳本**拉出來與實際計數並列：
```
帳本 emitted = [326, 326, 325]     ← 宣稱完全均衡
實際比例     = [0.3138, 0.3973, 0.2889] ← 明顯偏斜
```
帳本與現實不一致 → 補償一直對著假數字調節，「認為」沒事要做。

**根因**：`assign_families_and_pairs` 的 `if n_free == 0: return` 跳過記帳。
整批 slot 都被互動配對佔用時走這條路，該批 slot 永不入帳。實測 500 批中 **74 批**如此。

**只在小批次爆發**：sim 幾乎一次注入一個 env。batch=1 → 4.80pp；1-3 → 0.41pp；1-11 → 0.09pp。
原測試用 batch 1-11 **剛好避開實際的 batch=1**，全綠卻沒攔到。

**Why**：我先後猜「收斂慢」「四捨五入」兩次都被實測推翻。真因只有拉出內部狀態比對才看得見。

**How to apply**：
- 有提早返回的函式，**每一條返回路徑**都要檢查副作用（記帳/統計/狀態更新）。最容易漏的是
  「這批沒事做」的快速路徑 —— 但「沒事做」≠「不用記錄」
- 補償/校正機制失效時，**先把內部狀態與外部觀測並列**，不要猜機制
- 測試的參數範圍必須涵蓋**生產環境實際**範圍，不是「看起來合理」的範圍
