## 🛡️ 二、碰撞懲罰系統改進

### 2.1 方向性懲罰（新增）

**文件**：`mdp/rewards/safety_rewards.py`

**核心設計**：
- 只有「朝障礙物前進」才重罰
- 距離近 + 朝向障礙物的速度大 → 懲罰急遽增加
- 距離近但側向移動 → 懲罰變小

**實現邏輯**：
```python
# 計算機器人速度在「朝向障礙物」方向上的投影
velocity_toward_obstacle = dot(robot_vel, obstacle_direction)

# 使用平方函數：讓高速朝障礙物前進的懲罰急遽增加
directional_multiplier = 1.0 + 2.0 × (speed_ratio²)  # [1.0, 3.0]

# 只在危險區域應用（距離 < 0.8m）
penalty = base_penalty × directional_multiplier
```

**效果示例**：
```
場景 1：距離 0.5m，朝障礙物前進 1.5 m/s
  → 基礎懲罰：1.2（非線性）
  → 方向性係數：3.0（平方函數）
  → 組合懲罰：1.2 × 3.0 = 3.6
  → 最終：-3.6 × 0.5 = -1.8 分/步（增加 4.5 倍！）

場景 2：距離 0.5m，側向移動
  → 基礎懲罰：1.2（非線性）
  → 方向性係數：1.0（側向移動）
  → 組合懲罰：1.2 × 1.0 = 1.2
  → 最終：-1.2 × 0.5 = -0.6 分/步（允許側向避障）
```

**目的**：
- 直接瓦解「一頭撞上去」策略
- 允許靈活的側向避障

---

### 2.2 非線性懲罰（新增）

**文件**：`mdp/rewards/safety_rewards.py`

**核心設計**：
- 危險區域（0.8m > 距離 >= 0.4m）：使用平方函數
- 碰撞區域（距離 < 0.4m）：使用反比函數

**實現邏輯**：
```python
# 區域 1：danger_distance 到 collision_distance（中等懲罰，平方）
linear_penalty = 0.5 + 0.5 × (1.0 - (distance - collision_distance) / (danger_distance - collision_distance))
penalty = linear_penalty²  # 平方：讓懲罰曲線更陡峭

# 區域 2：距離 < collision_distance（最大懲罰，反比）
inverse_penalty = 1.0 + (collision_distance / distance - 1.0)
penalty = clamp(inverse_penalty, 1.0, 5.0)  # 限制最大懲罰為 5.0
```

**效果**：
- 讓 0.6m 以內「非常不舒服」
- PPO 在還沒撞之前就「心理崩潰」
- 直接瓦解「一頭撞上去」策略

---

### 2.3 完整懲罰計算流程

```
步驟 1: 計算基礎距離懲罰（非線性）
   距離 >= 1.5m: 0.0
   1.5m > 距離 >= 0.8m: 線性 0.0 到 0.5
   0.8m > 距離 >= 0.4m: 平方 0.5² 到 1.0²
   距離 < 0.4m: 反比函數（急遽增加）
        ↓
步驟 2: 應用方向性懲罰（只在危險區域）
   計算速度在「朝向障礙物」方向上的投影
   使用平方函數：multiplier = 1.0 + 2.0 × (speed_ratio²)
   懲罰 = 基礎懲罰 × multiplier
        ↓
步驟 3: 應用權重
   最終懲罰 = 懲罰值 × (-0.5)
```

**配置位置**：`cfg/charge_env_cfg.py` 中的 `progressive_collision` 獎勵項

## 🎯 三、目標生成系統修復

### 3.1 考慮障礙物半徑的碰撞檢查

**文件**：`goal_command.py`

**問題**：
- 原邏輯只檢查目標與障礙物中心點的距離
- 沒有考慮障礙物的實際半徑（0.2-0.5 米）
- 導致目標可能生成在障礙物內部或邊緣

**修復**：
```python
# 獲取障礙物尺寸（如果可用）
from .mdp.core.state import get_obstacle_sizes
obstacle_sizes = get_obstacle_sizes()

# 計算所需的最小距離（安全距離 + 障礙物半徑）
required_distances = obstacle_safe_distance + obstacle_radii

# 檢查每個障礙物：目標與障礙物中心的距離是否大於所需距離
clear_per_obstacle = distances_to_obstacle_centers > required_distances
```

**效果**：
- 目標與障礙物邊緣的距離至少為 `obstacle_safe_distance`（1.0 米）
- 避免目標生成在障礙物內部或邊緣
- 不同大小的障礙物使用不同的安全距離

## 🚀 四、新增獎勵函數

### 4.1 移動獎勵 (R_move)

**文件**：`mdp/rewards/motion_rewards.py`

**設計公式**：
```python
reward = k × (speed_x + b) × weight
```

**參數**：
- `speed_x`：機器人本體座標系 X 軸正向速度（前進方向）
- `k`：係數（默認 1.0）
- `b`：偏移量（默認 0.0，可設為負值以鼓勵更高速度）
- `weight`：權重（配置中設為 0.2）

**實際效果**：
```
speed_x = 0.0 m/s → 0 分（靜止，無獎勵）
speed_x = 0.5 m/s → +0.1 分/步
speed_x = 1.0 m/s → +0.2 分/步
speed_x = 1.5 m/s → +0.3 分/步
```

**目的**：
- 鼓勵車輛保持移動，避免因恐懼碰撞而停滯
- 確保 X 軸正向速度越高分越高

**配置位置**：`cfg/charge_env_cfg.py` 中的 `move` 獎勵項

---

### 4.2 對齊獎勵 (Alignment)

**文件**：`mdp/rewards/goal_rewards.py`

**核心設計**：
1. **基礎對齊獎勵**：車頭朝向與目標方向的夾角越小，獎勵越高
   ```python
   alignment_reward_base = cos(朝向角度)  # [0, 1]
   ```
   - 正對目標（0°）→ +1.0
   - 側對目標（90°）→ 0.0
   - 背對目標（180°）→ 0.0（不懲罰）

2. **未對準懲罰**：若車頭未對準目標但 Speed_x 很高，給予懲罰（防止衝過頭）
   ```python
   # 懲罰條件：未對準（> 72°）且高速前進（speed_x > 1.0 m/s）
   penalty = misalignment × speed_excess × penalty_scale
   ```

**實際效果**：
```
場景 1：正對目標（0°）+ 1.0 m/s
  → 基礎獎勵：+1.0 × 0.15 = +0.15 分/步
  → 懲罰：0（已對準）
  → 總獎勵：+0.15 分/步

場景 2：側對目標（90°）+ 1.5 m/s（衝過頭）
  → 基礎獎勵：0.0 × 0.15 = 0 分
  → 懲罰：-0.01875 分/步
  → 總獎勵：-0.01875 分/步（防止衝過頭）
```

**設計理念**：
- 由於車輛不能側移，「車頭朝向目標」變得至關重要
- 在 ROS 系統測試中，為了讓 Agent 準確抵達，加入了「比例控制器」概念
- 在 RL 獎勵中，加入對齊獎勵可以引導 Agent 先對準方向再加速
- 防止 Agent「衝過頭」：高速前進但方向不對

**配置位置**：`cfg/charge_env_cfg.py` 中的 `alignment` 獎勵項

## 🎯 七、設計優勢

### 7.1 最小改動原則

所有改動遵循「最小改動、但改到痛點」的原則：
- 只修改必要部分，保持現有結構
- 針對痛點進行精準改進
- 向後兼容：可通過參數開關啟用/禁用新功能

### 7.2 協同效應

各獎勵函數協同工作：
- **移動獎勵** (`move`)：鼓勵保持移動
- **對齊獎勵** (`alignment`)：引導正確朝向
- **朝向獎勵** (`heading_to_goal`)：根據距離動態調整朝向重要性
- **速度獎勵** (`velocity_toward_goal`)：獎勵朝目標移動的速度
- **方向性懲罰**：防止「一頭撞上去」
- **非線性懲罰**：讓危險區域「非常不舒服」

這些獎勵共同作用，引導 Agent 學習：
1. 保持移動（避免停滯）
2. 對準目標方向（先對準再加速）
3. 朝目標移動（速度與方向結合）
4. 安全避障（側向移動而非直撞）
