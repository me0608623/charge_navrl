```python
elif normalized == "mixed":
    flat_count = count * 2
    offset = int(torch.randint(0, 3, (1,), device=device).item())
```

## 6b. 機制假設稽核（Codex 提出，監督端於程式碼層級驗證）

**程式機制確認存在，因果仍待 A/B 驗證。** 以下三個環節在程式碼層級逐一核對為真；但「此機制導致 random_2d 失敗」的因果尚未證實，須由 §7 的 pause A/B 判定：

**① 障礙到點後暫停時，速度被硬歸零**（`rule_behaviors.py:138`）：
```python
sched.velocities[r_env, r_obs] = 0.0
```
不是「變慢」，是**設為精確 0.0**。

**② future-occupancy 用速度門檻篩掉靜止障礙**（`clean_progress.py:264-268`）：
```python
moving = obstacle_vel.norm(dim=-1) >= self.future_occupancy_move_threshold_mps   # 預設 0.1
valid  = moving & near
valid_separation = torch.where(valid, min_separation, inf)
```
速度 0.0 < 0.1 ⇒ `valid=False` ⇒ separation=inf ⇒ **risk 恆為 0**。暫停中的障礙對 reward 而言**完全不存在**，不是「權重低」而是「看不見」。

**③ 外推是純等速，不含反向**（`clean_progress.py:262`）：
```python
obstacle_path = obstacle_pos + obstacle_vel * times
```
障礙在 waypoint 反向後，暫停前的預測方向與實際**相反**。

### 為什麼偏偏是 random_2d：巡邏路徑長度差 4.6 倍

三家族 waypoint 幾何（`long_corridor_replay_geometry.py:284-330`），障礙速度 U(0.30, 0.60)、dt=0.2s：

| 家族 | 單程長度 | 單程步數 | 到點頻率 | **暫停隱形時間佔比** |
|---|---|---|---|---|
| longitudinal | 6.80 m（y −3.4→+3.4） | 76 | 1× | **3.2%** |
| lateral | ~3.30 m（橫越 free_width 4.0m） | 37 | 2.1× | **6.4%** |
| **random_2d** | **1.49 m**（Δy~1.35 + Δx~0.5） | **17** | **4.6×** | **13.1%** |

random_2d 的 waypoint 被刻意限制在窄帶內（y 分兩段 U(−3.3,−2.1)/U(−1.8,−0.8)，x 僅 ±0.15~0.35），**單程只有 1.5m**，因此到點、暫停、反向的頻率是 longitudinal 的 4.6 倍、lateral 的 2.1 倍。

**隱形時間佔比的排序（3.2% / 6.4% / 13.1%）與三家族 CR 排序（5.98% / 6.87% / 32.90%）一致。**

⚠️ **排序一致 ≠ 充分解釋**：隱形佔比 random_2d 只有 lateral 的 2.05 倍，CR 卻是 4.8 倍。此機制與觀測相容，但不足以單獨解釋整個落差。

### ⚠️ 證據邊界（本節結論可主張與不可主張的範圍）

**可主張**：程式機制確實存在——暫停時速度被硬歸零、低於 0.1 m/s 門檻、future-occupancy risk 恆為 0；且 random_2d 的到點/暫停/反向頻率是其他家族的 2.1–4.6 倍。這兩點都是程式碼與幾何的事實。

**不可主張**：以上**不足以認定 future-occupancy reward 是 D1 訓練失敗的根因**。

- pause A/B 跑的是**固定 policy 的評估**。它能回答「停留時間是否增加*現行 policy* 的碰撞」，**不能單獨證明訓練失敗的因果**——後者需要訓練側介入（本輪明確禁止）。
- **`zero` 模式並未消除全部 stationary-blind frame。** `rule_behaviors.py` 在 `reached` 分支內**無條件**執行 `velocities = 0.0`，不在 pause 分支下；即使 `pause_steps_range=(0,0)`，每次到點仍有一幀速度為零。`zero` 移除的是額外 **dwell**，不是全部靜止幀。
- 連帶的判讀注意：`zero` 模式下到點幀 `pause_remaining == 0`，會被歸類為 `post_switch_or_resume_1s` 而非 `paused`。**`zero` run 的 `paused` 桶為空是正確行為**，那些靜止幀移到了 post-switch 桶，不是消失了。
- 「反向」本身是與「暫停隱形」**可分離**的第二個因子：random_2d 每 17 步 180° 反向一次，等速外推在反向前後都給錯誤預測。A/B 設計應分開這兩者，否則 pause 門檻未達標也不能反推反向無影響。
