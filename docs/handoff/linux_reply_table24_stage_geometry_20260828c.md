## 起因

程式碼查證發現表 2.4 的「長走廊場景尺寸　約 58 × 20 m（x 向 ±29 m、y 向 ±10 m）」
在現行血緣不成立。

那組數字本身沒有錯，它出自
`source/.../charge_skrl/mdp/wall_layout.py:78` 的 `BOUNDARY_WALLS_T_CORRIDOR`
（註解即「T 字型走廊：58×20m 場景 + 2 個填充塊」，可行走區 bar
`x∈[-28.5,+28.5], y∈[+6.0,+9.5]`、stem `x∈[-3.5,+3.5], y∈[-9.5,+6.0]`）。

但該場景只掛在四個 `-TCorridor` 結尾的 gym task id 上
（`…-WD-TCorridor`、`…-NavRL-TCorridor` 及其 Play 版），
論文血緣用的 `…-Curriculum-WD` 走的是另一個 scene class。實際跑過的只有三支，
全在 2026 年 5 月、`curriculum_version=wd_tcorridor_v1`、`algorithm=a2c`：

| run | 日期 |
|---|---|
| `sa5_tc_g1_p30_ne1024_s42` | 2026-05-22 |
| `sa6_tc_dense_ne1024_s42` | 2026-05-23 |
| `sa7_tc_dense_ne1024_s42` | 2026-05-26 |

早於 v3（06-08）與 sim2real v2（07–08 月）。第五、六章的 SA1–SA6 一支都不是它。

**關鍵差異**：現行的長走廊不是一個獨立場地，而是**在同一方形場地內部**用兩道側牆
夾出來的通道。程式明文要求側牆跨距 = 場地全寬並密封至南北邊界牆
（`long_corridor_replay.py:110` `wall_span_length = 2.0 * room_half_extent`；
`:123-127` 若 `boundary_overlap < 0` 直接 raise）。因此走廊的外框就是場地外框，
沒有任何 58 公尺的 x 向延伸。
